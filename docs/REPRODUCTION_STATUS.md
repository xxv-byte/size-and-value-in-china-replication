# 复现状态登记表（REPRODUCTION_STATUS）

本文件回答唯一一个问题：**论文的每一块实验，在本仓库里处于什么状态。**

状态定义（互斥，按证据强度排序）：

| 状态 | 含义 |
|---|---|
| **已复现** | 有代码入口 + 在本轮**实际执行过**（合成样例或真实数据），产出可核对的数值 |
| **代码就绪（历史运行）** | 代码入口完整、可运行；数值来自 2026-10 的一次完整真实数据运行，**本轮未重跑** |
| **部分复现** | 主体已算，但存在代理变量、口径差异或样本缺口 |
| **仅框架/未完成** | 函数或表格在，但缺关键输入，只能输出"覆盖缺口" |
| **未实现** | 没有对应实现 |

> **本轮验证范围**：合成样例上的端到端运行（`run_sample_pipeline.py`）与 25 项测试已实际执行；
> 真实数据（约 12 GB）下的完整重跑**未执行**（见文末"为什么没有重跑"）。
> 因此下表中"历史运行"一列的数字，均来自 `06_reproduction_report.ipynb` 记录的那次运行，
> 不代表本次重新验证。

## 3. 与原文的已知差异（按影响排序）

1. **样本月份**：论文 204 个月，本地 199 个月。严格实施"形成月至少 15 个交易日"后，
   2000-03、2001-02、2002-03、2004-02、2005-03 五个月自然缺失，**没有放宽条件补齐**。
2. **数据源**：WIND → RESSET。同一指标的口径（PB、EPS、股本、换手）可能不同。
3. **EP 与 ROE 的代理**：EPS 未扣非、未年化；ROE 直接用日表字段。两者都是**排序信号**，
   对单调变换不敏感，但会改变分组边界。
4. **无风险利率**：直接用 RESSET 的 `DRfRet/Monrfret`，未与论文的一年期存款利率逐项核对。
5. **股本分母**：`Fullshr` 未拆分 A 股与 A+B+H 总股本；论文的市值口径需要 A 股流通/总股本。
6. **财务口径**：不筛 `ConFlg`（合并/母公司），同一报告期可能取到母公司报表。
7. **壳价值与借壳**：本仓库只有"吸收合并"表，**不是**论文的 133 起借壳事件；
   30% 截断的依据只能做敏感性，不能复现 Fig. 2。
8. **美国样本、历史行业分类、CSRC 审批日**：完全缺失 → 对应表格标记为未实现。

## 4. 为什么没有在真实数据上重跑

- 日表全样本约 **18,217,775 行**（本机实测），一次 B 线运行要把它们读进内存并做多轮滚动计算，
  且 `%run` 累积链会让读取与特征重复多次（见 [RUNNING_GUIDE.md](RUNNING_GUIDE.md) §1.1）。
- 在本次整理任务的资源预算内，全量重跑不现实；**没有重跑就不能声称"重新验证通过"**，
  所以本文件把已有数字一律标注为"历史运行"。
- 已完成且可复现的验证替代方案：
  1. **静态检查**：31 个 Notebook 的 JSON 合法性、`%run` 目标存在性、函数定义齐全性、
     个人绝对路径扫描（`tests/test_notebook_integrity.py`，7 项）。
  2. **行为测试**：在合成小表上验证清洗、股票池、point-in-time 对齐、错期、动量、2×3 构造、
     十分位分组、时序/截面/FM 回归（`tests/test_core_logic.py`，18 项）。
  3. **样例端到端**：`scripts/run_sample_pipeline.py` 真实执行 9 个 Notebook 的全部代码单元，
     产出 `F(24×10)`、`F_ch3(23×3)`、`R(24×40)`、`B(10×40)`、`lambda_t(24×10)`。
  4. **真实数据静态检查**：`scripts/check_data_layout.py --deep` 对 40 个日表分片、
     18.2M 行做逐文件读取与主键检查，FAIL=0。
